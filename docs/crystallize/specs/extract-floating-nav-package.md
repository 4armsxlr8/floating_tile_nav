# Pinterest風の浮遊ナビを別のFlutterアプリから再利用できるパッケージにする

> 2026-09-05 合意済み。名称の採用指示と、残る動作・責務についての「推奨でOK」をもって確定。パッケージ化後の見た目と操作感は実機で再確認する。

## 課題
現在の浮遊ナビは単独サンプルの内部部品で、ホーム・検索・プロフィール、アイコン、読み上げ名、色と寸法が固定されている。別のアプリで使うには実装をコピーして編集する必要がある。

## 解決
浮遊ナビをローカル参照できるFlutterパッケージとして提供する。利用側は項目、選択状態、タップ時の処理、色と寸法を指定できる。今の3画面サンプルはパッケージを使う実行可能な利用例として残す。

## 要件
- パッケージ名はfloating_tile_navとする。別のFlutterアプリからパス指定で依存し、公開入口だけをimportして利用できる。内部実装やデモを直接importする必要はない。
- 項目の指定を省略した場合、現在の独自アイコンによるホーム・検索・プロフィールの3項目を提供する。一般的なMaterialアイコンへの置き換えで見た目を変えない。
- 利用側は2〜5項目を指定できる。各項目は通常アイコン・選択アイコンをWidgetで受け取り、空白だけではない読み上げ名を必須とする。表示順は指定順を維持し、同じ読み上げ名の項目も番号で区別する。可視の文字ラベルは追加しない。
- 既定3項目の独自アイコンも利用側から再利用でき、既定アイコンと利用側のアイコンを混在できる。読み上げ名は利用側で言語を差し替えられる。翻訳の自動選択は行わない。
- 選択状態は利用側が渡した番号に従う。タップだけで内部の選択状態は更新しない。画面切り替え・画面履歴・スクロール位置の管理は利用側が担当する。
- 正常なタップ1回につき、その項目番号を1回通知する。選択済みの項目の再タップも通知し、利用側が無視するか別の処理をするか決める。デモは従来どおり再タップを無視し、先頭に戻らない。
- 指を外して離す、またはジェスチャーをキャンセルした場合、通知せず押下表示を戻す。読み上げによるタップでも同じ項目番号を1回通知する。
- 設定可能な見た目はボタン背景色、アイコン色、ボタン寸法、間隔、角丸、アイコン寸法、下端の最小余白とする。初期値は順に#32332d、白、52、8、16、28、32（寸法は論理ピクセル）。利用側Widgetが明示した色や寸法はそのWidgetの指定に従う。
- 押下時は120msで0.88倍に縮小し、離す・キャンセルで戻る。タップ領域は縮めない。今回、アニメーション設定は公開しない。
- ナビを配置する画面とコンテンツの末尾余白は利用側が用意する。標準の組み込み例は下部中央へ重ね、スクロール中も常時表示する。ナビが利用側コンテンツの余白を自動編集することはない。
- ナビ自身が安全領域を考慮する。下余白は設定された最小値とOSの安全領域の大きい方とし、左右の安全領域も避ける。利用側で安全領域を管理する場合はナビ側の適用を無効にでき、その場合も指定した最小下余白は残る。
- 不正な設定はデバッグ・リリースの双方でArgumentErrorとして拒否し、黙って補正しない。対象は項目数0・1・6以上、範囲外の選択番号、空白だけの読み上げ名、有限でない寸法、48未満のボタン寸法、負の間隔・角丸・最小下余白、ボタン寸法の半分を超える角丸、0以下またはボタン寸法を超えるアイコン寸法とする。
- 利用側が項目を減らす際は、有効な選択番号を同じ更新で渡す。古い範囲外の番号を自動で末尾に置き換えない。
- ナビは横一列で表示する。画面幅を超える独自寸法に自動縮小・折返し・横スクロールは行わず、利用側が収まる設定を選ぶ。説明に必要幅の計算方法（ボタン寸法×項目数＋間隔×項目間の数）と安全領域を引いた使用可能幅との比較を示す。
- 既存の3画面、ダミー内容、スクロール位置保持、Webの日本語フォントとオフライン資材読込みを利用例に維持する。本体はデモ・フォント素材・アプリ全体のテーマに依存しない。
- README と CHANGELOG は英語で書く (pub.dev の読者向け。日本語のままにすると海外の利用側が読めない)。README にローカル参照、既定3項目、独自項目、色と寸法、安全領域、コンテンツ余白、再タップ処理の利用例を含める。利用例アプリの UI 文字列とテスト名は日本語のままでよい。
- 公開されるファイル (README・CHANGELOG・description・利用例の UI 文字列・クラス名・コードコメント・Android/iOS/web の識別子と表示名) に Pinterest の商標を含めない。利用例の表示名とヘッダ文字は "Floating Tile Nav"、クラス名は FloatingTileNavDemoApp、識別子は com.example.floating_tile_nav_example (iOS は com.example.floatingTileNavExample) とする。= 端末に入っている従来の開発ビルドは別アプリ扱いになる (2026-09-07 改訂。旧「識別子を維持」を上書き)

## 非機能要件
- iOS/Androidのスマートフォン縦向きと確認用Webを対象とする。サンプルに新しいネイティブ機能や実行時の外部通信を追加しない。
- 本体の実行時依存はFlutter SDKだけとする。
- 本体は `package:flutter/widgets.dart` (と painting 等の下位ライブラリ) のみに依存し、`package:flutter/material.dart` を import しない。Material 固有の色や部品が要る場合は本体で定数として持つ。material.dart を import すると、Material の material_ui パッケージへの分離 (Flutter 3.47 で 1.0、次期 stable で SDK 内の material.dart が deprecated 予定) の際に本体側の移行がメジャーバージョンアップ扱いになるため。
- 既定の寸法で2〜5項目が幅320〜430の画面内に収まる（左右の安全領域が0の場合）。左右に安全領域がある場合は、そこを除いた幅に収まる設定を利用側が選ぶ。
- 全項目のタップ領域は48×48以上を維持し、読み上げでボタン名と選択状態を取得できる。既定アイコンは塗りと線画で選択を区別する。独自アイコンの視覚的な区別は利用側が指定する。
- 対応SDKの下限は既存プロジェクトの設定から引き下げない。旧SDKへの対応追加を今回の要件としない。

テストしないと決めたもの:
- 検索・認証・保存・通信 — 既存同様スコープ外。
- 利用側が渡す任意Widgetの内部動作やレイアウト違反 — 利用側の責務。指定Widgetの表示とナビの通知は検証する。
- pub.devの公開審査や配布 — 今回はローカル利用まで。
- 旧SDK、タブレット専用設計、キーボード操作の追加 — 今回の対応追加に含めない。

実機確認に委ねる基準:
- 既存の独自アイコン・角丸・間隔・下部中央位置・押下反応がパッケージ化前と同等であること。
- 別アプリへの組み込みで設定したアイコンと色が意図どおりに見えること。

## スコープ外
- pub.dev公開とそのための公開ライセンス決定・公開審査対応。名称は今回の認識合わせで決める。
- 新しい画面遷移シェル、ルーター、状態管理ライブラリ。
- 自動非表示、再タップ時の自動スクロール、アプリ再起動後の復元。
- 6項目以上、横スクロール・折返し・幅に応じた自動縮小。
- アニメーションのカスタマイズ、バッジ、可視ラベル、自動翻訳。

## 用語
- **既定3項目**: 現在の独自アイコンによるホーム・検索・プロフィール。
- **利用側**: パッケージに依存してナビを配置し、画面と選択状態を管理するアプリ。
- **利用例**: 現在の3画面デモを、パッケージの公開入口で組み直した起動可能なアプリ。
